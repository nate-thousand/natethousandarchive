# Contributing

Design OS should stay small enough to use.

## Contribution Rule

Add something to this repository only when it is reusable across two or more unrelated products.

## Workflow

1. Identify the recurring problem.
2. Check whether an existing principle, token, component, pattern, prompt, or template already covers it.
3. Add the smallest reusable improvement.
4. Update the relevant README or core document.
5. Record meaningful changes in `CHANGELOG.md`.

## Avoid

- Empty placeholder folders.
- Vague best-practice documents.
- Product-specific assets or implementation code.
- Required templates that you would not actually use.
